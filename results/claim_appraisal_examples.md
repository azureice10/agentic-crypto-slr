# Claim appraisal examples and Table 3.8b

Recorded release-3.6.3 appraisal history, retained for traceability. These examples are not new primary-source findings by the CS1 revision. READY applies to a bounded claim; it does not automatically release every attached metric. Exact claims and locators are in data/claims.csv.

Our dual-reviewer full-text audit identified **102 claims (`17.5%`: `49` Tier 1 and `53` Tier 2)** where the authors' stated guarantees were only partially supported (`101`) or directly contradicted (`1`) by the evidence in the PDF. Across these 102 claims (identified by `Claim_Support_Status` in `data/claims.csv`; the internal `TABEL_08` worksheet is not distributed), five recurring methodological failure patterns account for the evidentiary gaps:

1. **Fundamental cryptographic construction errors (`NOT_SUPPORTED` and broken primitives):** In `ARXIV-S-0245` (`CLM-0446`, paired with prototype claim `CLM-0445`) \[49\], the sole claim rated `NOT_SUPPORTED`, the author defines a *"cryptographic digital signature"* for Byzantine fault-tolerant medical agent messaging in Equation 3 as an **unkeyed `SHA-256` hash** ($\sigma_m = \text{SHA256}(\text{id} \parallel \text{type} \parallel \text{content} \parallel t \parallel \text{sender})$), which provides zero sender authenticity or unforgeability against any adversary capable of reading or constructing the message fields. Similarly, multiple studies (`ConvPayMAS` `SLR-M-0125`, `Integrated Framework` `SLR-M-0178`, `Lineage` `SLR-M-0188` \[6\]) conflate symmetric `HMAC-SHA256` shared-secret tags with public-key non-repudiation across mutually distrusting administrative domains.

2. **Simulated cryptographic primitives and pseudo-logs reported as real implementations:** In `AITH` (`ARXIV-S-0203`: `CLM-0420`, `CLM-0421`, and coupled audit claim `CLM-0422`) \[48\], the text claims a post-quantum `ML-DSA-87` delegation protocol achieving `0.21 µs` verification, but inspection of the implementation methodology reveals that `ML-DSA-87` was simulated in Python using `HMAC-SHA256`. In `ARXIV-S-0278` (`CLM-0041`), a 500,000-iteration `Z3` SMT state-pruning log is explicitly labeled in Appendix C (p. 23) as a *"pseudo-log output"* while the actual open-source prototype uses a 12-node `NetworkX` boolean flag without `Z3`. Similarly, `LLM-Redactor` (`CLM-0042` / `ARXIV-S-0386`) \[63\] evaluates `FHE`, `MPC`, and split inference via simulated `10 ms` protocol stubs, `SLR-M-0018` (`CLM-0147`) demonstrates timing patterns via a standalone HTML/JS weak-PRNG demo without implementing its proposed `TEE` or memory-hard `PoW` gates, and `CapSeal` (`CLM-0001` / `SLR-M-0219`) \[41\] benchmarks a non-cryptographic 16-round mult-XOR stand-in while claiming 256-bit PRF security on p. 15.

3. **Unpopulated experimental placeholders and internal table-versus-prose contradictions:** `ARXIV-S-0287` (*Verifiable Manifest Signing*, `CLM-0474`) \[53\] prints literal `[specify]` placeholders in `Table II (p. 8)` for the signature algorithm (`ECDSA`/`Ed25519`), model parameters, and hardware configuration. In `EquiMem` (`ARXIV-S-0511`, `CLM-0577`) \[76\], prose claims `82.1%` accuracy outperforming baselines whereas `Table 1` prints `62.0%` vs. `68.0%` (`Table 7` also prints `6.4%–9.7%` runtime overhead vs. `<5%` in prose). In `SafeAgent` (`ARXIV-S-0502`, `CLM-0575`) \[103\], `Table II` prints `direct_harm = 0.3157` alongside an impossible `Total = 0.0000`. In `ARXIV-S-0196` (`CLM-0418`), prompt-anchor thresholds are tuned directly on the errors of the same 100-prompt test set (*train-on-test leakage*) without a held-out AUC evaluation. Additional internal contradictions include million-fold unit discrepancies (`3.1 ms` native vs. `3.15 ns` Wasm in `SLR-M-0166` `CLM-0230`), protocols transmitting plaintext Chain-of-Thought steps (`SLR-M-0174` `CLM-0235`) or plaintext medical queries $q$ in $Q^*={q,x^*}$ (`SLR-M-0233` `CLM-0267`) while claiming query privacy, omitting `result_count` from the printed `HMAC` input formula (`ARXIV-S-0020` `CLM-0062`), mislabeling fractional precision $\lambda=26$ as *"26-bit cryptographic security"* (`SLR-M-0234` `CLM-0268`), or printing explicitly *"illustrative"* non-empirical tables (`SLR-M-0102` `CLM-0196`).

4. **Denominator errors and precision/false-positive conflation:** In `ARXIV-S-0329` (*MCP Privacy Detector*, `CLM-0496`/`0497`) \[56\], the authors claim a `4%` False Positive Rate and *"zero false negatives"* after manually inspecting only `200` servers that their tool had *already flagged as positive* (`192/200 = 96.0%` is positive predictive value / precision, leaving negative predictions completely uninspected). In `Connor` (`ARXIV-S-0451`, `CLM-0556`) \[101\], a malicious-MCP detector achieves `98.4%` precision on a balanced benchmark, but in its wild scan of `1,672` real-world servers it raises `9` alerts of which `7` are false positives (`22.2%` real-world precision).

5. **Static risk scores diverging from runtime exploitability:** `MCP Pitfall Lab` (`ARXIV-S-0345`) \[58\] demonstrates that hardening an MCP server to reduce its static Tier-1 risk score from `10` to `0` simultaneously *increased* runtime document-injection ASR from `8.3%` to `25.0%`, proving that static code hygiene checklists cannot substitute for runtime `B2/B3` enforcement.

To operationalize a rigorous, reproducible release gate across the entire 584-claim dataset under `stage3_quality.py` (which permits `PARTIALLY_SUPPORTED` claims to enter `Claim_QA = READY` under `Verification_Status = ADJUDICATED` only when their valid sub-scope is explicitly fenced and all linked metrics are resolved, while strictly blocking `NOT_SUPPORTED`), we audited all `107` candidate `FLAGGED` claims (the `102` `PARTIALLY`/`NOT_SUPPORTED` claims, `1` coupled `AITH` sibling `CLM-0422`, and `4` `SUPPORTED_WITHIN_SCOPE` claims from two early-access 2027-dated journal/proceedings papers `SLR-M-0139` and `SLR-M-0289`). Table 3.8b summarizes the resulting **strict decision boundary (`Paket B`)**, which promotes **53 verified/fenced claims (`P1` + `P2`) to `READY`** (bringing the total released corpus to **`530/584` claims; `90.8%`**) and retains **54 claims (`9.2%`) at `FLAGGED`**.
